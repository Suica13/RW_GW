# RW_GW_BU
RW高达战争_战争宇宙Mod

Main/主包
用于存放通用信息和各类模板，且处理开始游戏的部分事件和单位
也包括部分标记用单位和通用计算用单位
（例如地图类型标记，TileMode检测发送单位，单位通用计算核心单位与伤害计算单位）

DLC/分包
用于存发系列别的单位，科技树，开始单位（基地等）
由于铁锈自己不能跨mod读取文件，所以在修改通用模板后请及时覆盖至Main/主包与其他DLC/分包中。
（例如技能模板/通用的光束军刀格斗武器模板/动画模板/通用子弹图片音效等）

图片文件统一用.png

宇宙世纪合并包（UC）
`GW_BattleUniverse_DLC_UC` 必须与 Main 一起启用，禁止同时启用其他 DLC。可选择 0079、0087、0093 三种剧本开局；原有年代包保持独立。每个时代的全部 T1/T2 主线科技合并为一页，每行从左至右排列。科技点门槛为原值的 56.25%，研究费用与研究时间保留；不保留独立支线科技节点；指定支线机体按 UC 专用规则并入主线。

完成当前时代全部主线，还需累计到该时代最终主线门槛后额外 2700 科技点，才能在 HQ 选择下一时代阵营。2700 来自 0079 GP 计划与吉莱计划的原始门槛差值 4800，再应用 56.25% 系数。年代升级不清空科技点，新时代的科技门槛在升级时的累计门槛上继续计算；资金、资源、现役部队与已完成研究保留。

每次进入下一时代追加一页并保留历史页，从 0087 或 0093 开局只显示该时代起实际经历的页面。联邦→奥古/提坦斯，吉翁→奥古/新吉翁；奥古→0093 联邦，提坦斯→0093 联邦/新吉翁，新吉翁→0093 新吉翁。AI 在满足相同研究与科技点要求后，随机选择当前阵营允许的下一时代阵营。原生工厂和建筑解锁规则保留，空闲工厂在新阵营同类工厂解锁后转换；AI 生产沿用各年代对应工厂的原生分组、随机区间、数量上限和 HQ 单次调度，不额外群发或绕过随机选择。

中英文独立加载提示仅出现在选择剧本之前的模式面板下方，显示尺寸缩小一半；火线纵横入口保留为 WIP。合包沿用其他 DLC 的 `Units/`、`Template/`、`Resource/` 目录及原始文件名；同路径不同配置增加年代后缀，不跨包读取资源文件。`uc-source-map.json` 记录配置的原始来源。

重建与静态校验入口为 `文档 (不要打包)/工具/宇宙世纪/build.ps1`。重建会从当前 Main、0079、0087、0093 源文件重新生成 UC 包，请先在源包修改再重建；若年代源包临时移动到上一级 `mods/`，工具也可从该位置读取。隔离引擎验证入口为同目录 `run_checks.ps1`，仅加载 Main 与 UC。

UC 专用科技合并规则位于 `文档 (不要打包)/工具/宇宙世纪/uc_technology_rules.py`，仅影响合并包，不改原年代 DLC。全装甲高达并入月神2，高达7号机／全装甲7号机并入吉莱，吉姆打击型／装甲强化型并入吉姆改；吉翁将阿普萨拉斯、水中型MA、高战蟹计划分别并入扎古II后期、次世代主力MS竞标、统合整备，老虎飞行试验型并入陆地用MS。兹达F、量产型强人和强人强化支线不进入 UC。
0087 的 S／Ex-S 计划分别并入 ZZ／新式吉姆III；高扎古特装型和EWAC高扎古并入玛拉塞，精神感应高达／MK-II计划分别并入拜亚兰／宇宙用TMS，改修型勇士并入强人改。主线科技点、经济需求及时代门槛保持原有 UC 规则。针对这些规则的验证清单由 `prepare_technology_runtime.py` 生成；运行 `run_checks.ps1 -TechnologyChanges` 执行科技、生产和形态验证。

UC 精简按真实获得与运行依赖收集：主线科技解锁、初始单位和明确的 ACE_Unit 专用机作为入口，再保留 ACE 信标、变形／脱出／状态切换、武器与炮塔依赖。解锁一台机体不会把同目录其他型号自动保留，旧 Get／Send 注册也不再构成保留依据；没有保留科技解锁的工厂生产项一并移除。仅用于继承的原单位输出为 `_Base.gw`，不作为独立单位加载。
UC 战斗单位的中英文显示名称按来源年代标注 `[0079]`、`[0087]`、`[0093]`，单位 ID、Tag 和消息引用保持原有命名。保留原因记录在重建输出 `output/uc/entity-retention.json`，用于追踪实际依赖。
UC 的 0079、0087、0093 开局均可选择 PMC，沿用 Main 的独立指挥部、空科技页、隐藏专用建筑槽和友军单位接管系统；没有其他友军玩家（含 AI）时禁止选择。PMC 不发放初始部队，也不加入普通阵营的跨时代科技路线。
UC 中 PMC 借用友军机体占领据点后，据点交给机体原所属队友，使用该队友的建筑科技与四个建筑槽；PMC HQ 的建筑限制保留。UC 科技翻页会先清除所有旧视觉页面，研究控制器继续保留进度。UC 各年代的 ACE 使用独立 PilotType 编号范围；ACE 转换按所选 PilotType 直接匹配保留的驾驶员，不受历史阵营标签影响，并等待初始化完成后重试。UC 的每轮 AI 生产调度按原年代逻辑选择生产建筑，保留原有费用、人口、数量上限和队列条件。

UC 工厂 AI 对照检查：运行 `文档 (不要打包)/工具/宇宙世纪/verify_uc_ai.py`，逐项核对原年代工厂；运行同目录 `run_checks.ps1 -AI` 验证七阵营科研、生产与时代推进。

UC 的射程、视野和探测计算复用同一次局部粒子查询；Main 实际战斗核心和 UC 模板同步采用此优化。运行同目录 `run_checks.ps1 -Range` 验证同次更新、不同单位隔离及原有数值修正。

PMC 指挥部不可被占领，AI 占领目标检索也会忽略它。PMC 基地不计入占领胜负数量，队友的普通基地全部失守后仍会判负。PMC 借用机体期间禁止驾驶员脱出；与友军机体交换驾驶员后，原机体归还原队伍，直接控制跟随换出的驾驶员转移到目标机体。常规坦克、飞机与相关状态已接入直接控制，适配文件位于对应单位的 `PlayerControl/` 文件夹，沿用原生武器消耗、连射和装填。
Main 的 `Maps/` 新增七张 `[p20]`、`[10v10]`、`_SP` 特殊地图：保留原 0/1 号基地位置，每队其余九个出生点以五格间距围绕本队基地排列，原地图继续保留。静态检查运行 `文档 (不要打包)/工具/宇宙世纪/verify_pmc_vehicles_maps.py`；同目录 `run_checks.ps1 -Vehicles` 检查 PMC 换乘与载具武装，`-Maps` 检查二十玩家地图。
